该仓库是一个 Vite + React Three Fiber 的单页静态站点，不存在后端意义上的运行时配置系统。项目中的“配置”集中在以下三个层面：

1. **构建期常量集中管理**：`src/constants.js` 以 ES module 形式导出 Cover Flow、卡片样式、导航栏动画、自定义光标、表单验证等 UI/交互参数，作为全局共享的“魔法数字”来源，组件直接 import 使用。

2. **Vite 构建配置**：`vite.config.js` 通过 `defineConfig` 声明 base、插件、依赖预打包（`optimizeDeps.include/exclude`）、代码分割（`manualChunks`）、压缩（`terserOptions.drop_console/drop_debugger`）以及开发服务器端口等；这些是纯构建期配置，不参与运行时代码。

3. **运行期环境注入**：仅有一处使用 Vite 注入的环境变量——`src/utils/path.js` 读取 `import.meta.env.BASE_URL` 来为静态资源拼接 GitHub Pages 部署时的 base 前缀；`.gitignore` 中列出了 `.env` / `.env.local` 模板但当前未实际使用任何 `.env` 文件。

整体而言，该项目没有独立的配置文件目录（如 `config/`、`*.yaml`、`application.properties`），也没有运行时配置加载器或 feature flag 机制；所有“可配置项”均以 JS 常量对象的形式内联在源码中，由开发者修改后重新构建生效。
