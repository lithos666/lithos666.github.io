本仓库为 Vite + React Three Fiber 单页作品集，未引入后端服务或专用错误上报 SDK，错误处理集中在浏览器端，采用以下策略：

1. **React 组件级 Error Boundary**
   - `src/components/HeroSection.jsx` 内定义类组件 `ErrorBoundary`，通过 `getDerivedStateFromError` 捕获子树渲染期异常，将 `hasError` 置为 `true` 后返回一个黑底「Loading...」占位 UI，避免整个应用白屏。
   - 该边界仅包裹 HeroSection 的 Canvas 与 3D 子组件（`RayMarchedBlackHole`、`PostProcessing` 等），属于局部隔离，不影响其他页面区域。

2. **图片资源加载失败容错**
   - `src/components/CoverFlowCarousel.jsx` 提供 `handleImageError`，在 `<img onError>` 中隐藏父容器，防止缺失图片导致布局错位。
   - 所有轮播卡片均通过此回调统一处理外部静态资源不可用的情况。

3. **输入校验与防御式编程**
   - `CoverFlowCarousel` 在函数体开头对 `projects` 做类型与空数组检查，不合法时 `console.warn` 并直接 `return null`，避免后续渲染崩溃。
   - 导航函数 `goTo` 使用 `Number.isFinite` 与循环回绕逻辑，防止越界索引引发状态异常。

4. **无全局中间件 / 无 Promise 错误聚合**
   - 代码库中未发现 `try/catch`、`throw`、`.catch()` 等异步错误处理模式，也未见自定义错误类型、错误码或 Sentry/LogRocket 等上报集成。
   - 3D 场景依赖 `Suspense` 配合 R3F 的懒加载，但并未为其配置 fallback 错误视图，异常仍由外层 `ErrorBoundary` 兜底。

开发者约定建议：
- 新增复杂交互组件时，若其渲染可能抛出异常，应自行包裹 `ErrorBoundary` 或使用现有边界。
- 对外部资源（图片、字体、模型）一律注册 `onError` 回调，以降级 UI 而非抛错。
- 如需业务层错误（如 API 调用失败），应在当前单页架构下通过状态管理或本地日志记录，保持与现有「UI 兜底 + 静默降级」风格一致。
